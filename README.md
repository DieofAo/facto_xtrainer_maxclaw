# FACTO XTrainer MaxClaw

> **FACTO**（Functional Adaptive Constrained Trajectory Optimization，函数空间自适应约束轨迹优化）算法在 XTrainer 6轴机械臂（MaxClaw 夹爪版本）上的完整复现。

## 项目简介

一句话概括：**给定机械臂的起始关节角和目标关节角，自动规划出一条平滑、避障、满足关节限制的运动轨迹。**

### 文件结构

| 文件 | 作用 |
|------|------|
| `facto_xtrainer.py` | **核心文件**：包含机器人模型 (`XTrainerRobot`)、基函数 (`FourierBasis`)、FACTO 优化器 (`FACTOFull`)、可视化函数 |
| `ik_solver.py` | **逆运动学求解器**：提供伪逆法、LM 法、FABRIK 启发式三种 IK 算法 |
| `xtrainer_arm.urdf` | **机器人 URDF 模型**：6轴机械臂的连杆、关节、惯性等物理参数定义 |
| `xtrainer.yml` | **碰撞球体配置**：各连杆上碰撞检测球体的位置和半径 |
| `environment.yml` | Conda 环境配置 |

## 算法原理

### 核心思想

传统的轨迹优化方法直接优化每个时间步的关节角，维度高、计算慢。FACTO 的核心创新是：

1. **用傅里叶基函数压缩轨迹表示** —— 把 `80个时间步 × 6个关节 = 480个变量` 压缩为 `10个基函数 × 6个关节 = 60个系数`
2. **在系数空间做 LM 优化** —— 参数少了 8 倍，而且天然保证平滑（高频被截断）

### 整体流程

```
输入: 起始关节角 start, 目标关节角 goal
  │
  ▼
Hermite 插值 (3t²-2t³) → 初始轨迹 (80×6)
  │
  ▼
trajectory_to_coeffs → 傅里叶系数 (10×6 = 60个数)
  │
  ▼
┌──── LM 迭代优化 (在系数空间) ────┐
│                                    │
│  计算代价函数 (残差向量 + 雅可比)：│
│    ① 平滑度代价 (加速度最小化)     │
│    ② 终点误差代价                  │
│    ③ 起始点约束                    │
│    ④ 速度边界约束 (起止速度=0)     │
│    ⑤ 关节限制代价                  │
│    ⑥ 障碍物避让代价                │
│                                    │
│  LM 更新: H·δ = Jᵀ·r             │
│  H = JᵀJ + λI  (自适应阻尼)       │
│                                    │
│  接受/拒绝判断 → 调整 λ            │
└────────────────────────────────────┘
  │
  ▼
coeffs_to_trajectory → 最终平滑轨迹 (80×6)
```

### 基函数设计

基函数矩阵 Φ 的列布局为：

```
[1, 3t²-2t³, sin(2πt), cos(2πt), sin(4πt), cos(4πt), ...]
 ↑    ↑          ↑
 |    |          └─ 傅里叶谐波（控制轨迹形状）
 |    └─ Hermite项（打破周期性 + 端点零速度）
 └─ 常数项（直流偏置）
```

Hermite 项 `h(t) = 3t²-2t³` 的特殊性质：
- `h(0)=0, h(1)=1` → 起终点可以取不同值
- `h'(0)=0, h'(1)=0` → 端点速度天然为零，不与速度边界约束冲突

选择傅里叶基的优势：
- **频率可控**：`n_basis=10` → 最高第4阶谐波，自动过滤抖动
- **解析求导**：速度 / 加速度直接由系数计算，无需数值差分
- **正交性好**：各基函数互不干扰，优化时不会相互"打架"

### LM 优化器

Levenberg-Marquardt 算法是高斯-牛顿法和梯度下降法的混合：

- **λ 小时**：接近高斯-牛顿法，步子大、收敛快
- **λ 大时**：接近梯度下降法，步子小、更稳当
- **自适应调节**：代价降低 → λ/1.5（更激进）；代价未降 → λ×1.5（更保守）

## 快速开始

### 环境安装

```bash
conda env create -f environment.yml
conda activate facto_xtrainer
```

依赖：`numpy`, `matplotlib`

### 运行测试

```bash
python facto_xtrainer.py
```

将生成两张可视化图片：
- `test_p2p.png` —— 点到点轨迹规划
- `test_obstacle.png` —— 带障碍物的轨迹规划

### 代码使用示例

```python
import numpy as np
from facto_xtrainer import XTrainerRobot, FourierBasis, FACTOFull

# 创建机器人和优化器
robot = XTrainerRobot()
basis = FourierBasis(n_basis=10, n_dof=6, n_points=80)
facto = FACTOFull(robot, basis)

# 定义起止关节角
start = np.array([0, 0, 0, 0, 0, 0])
goal = np.array([0.5, 0.3, 0.2, 0.1, 0.2, 0])

# 优化
traj, info = facto.optimize(start, goal, max_iter=200)

# traj: (80, 6) 的轨迹矩阵，每行是一个时刻的6关节角
print(f"迭代次数: {info['iterations']}, 最终代价: {info['final_cost']:.4f}")
```

带障碍物：

```python
obstacles = [np.array([0.2, 0.1, 0.2])]  # 障碍物坐标
traj, info = facto.optimize(start, goal, obstacles=obstacles, max_iter=200)
```

## 近期修改记录：轨迹平滑度修复

### 问题现象

原始版本生成的关节曲线存在**明显波动**，不够平滑，起止点精度差。

### 根本原因分析

经过诊断，发现 **4个问题**：

| # | 问题 | 严重程度 | 说明 |
|---|------|----------|------|
| 1 | **纯傅里叶基函数的周期性锁死** | 🔴 致命 | `sin(nωt)` 和 `cos(nωt)` 在 `t=0` 和 `t=1` 处取值完全相同，导致 `Φ(0)=Φ(1)`，**无论怎么调系数，都只能生成 traj[0]=traj[-1] 的轨迹**，无法表示不同起止点 |
| 2 | **LM 接受条件使用 `sum(cost)` 而非 `sum(cost²)`** | 🔴 致命 | 残差可正可负，直接求和会互相抵消，导致优化器错误地接受/拒绝更新，引发发散 |
| 3 | **平滑权重过低** (0.001) | 🟡 中等 | 平滑度代价被终点误差代价 (权重10) 和关节限制代价 (权重5) 碾压，优化器几乎忽略平滑性 |
| 4 | **缺少起始点约束和速度边界约束** | 🟡 中等 | 起始点可自由漂移引入高频补偿；端点速度不为零导致曲线"冲入冲出" |

### 修复内容

#### 修复 1：基函数加入 Hermite 项 `3t²-2t³`（打破周期性 + 端点零速度）

```
修复前: [1, sin(2πt), cos(2πt), sin(4πt), cos(4πt), ...]
修复后: [1, 3t²-2t³, sin(2πt), cos(2πt), sin(4πt), cos(4πt), ...]
             ↑
          Hermite项：h(0)=0, h(1)=1, h'(0)=0, h'(1)=0
```

Hermite 项同时解决了两个问题：
- **打破周期性**：`h(0)=0 ≠ h(1)=1`，起终点可以取不同值
- **端点零速度**：`h'(0)=h'(1)=0`，不会与速度边界约束冲突

之前使用线性项 `t` 时，虽然解决了周期性，但 `d(t)/dt=1` 导致端点速度 ∝ (goal-start)，大目标时速度代价爆炸，轨迹退化为直线。

初始化轨迹也同步改为 Hermite 插值 `start + (3t²-2t³)·(goal-start)`，确保初始系数集中在 Hermite 项上，不泄漏到傅里叶谐波。

#### 修复 2：LM 接受条件改为残差平方和

```python
# 修复前（错误）
if np.sum(cost_new) < np.sum(cost):  # 正负抵消，判断失误

# 修复后（正确）
if np.sum(cost_new**2) < np.sum(cost**2):  # 残差平方和才是LM的目标函数
```

#### 修复 3：调整代价权重

| 代价项 | 修复前 | 修复后 |
|--------|--------|--------|
| 平滑度 | 0.001 | **0.1** (×100) |
| 终点约束 | 10 | **50** (×5) |
| 起始点约束 | 无 | **50** (新增) |
| 速度边界 | 无 | **5.0** (新增) |
| 关节限制 | 5 | 5 (不变) |

#### 修复 4：新增起始点约束和速度边界约束

- **起始点约束** (`_jacobian_start`)：约束 `traj[0] == start`，防止起点漂移
- **速度边界约束** (`_jacobian_velocity_boundary`)：约束起止速度为 0，消除端点冲击

#### 修复 5：性能优化 - 预缓存矩阵

`FourierBasis` 的基矩阵、速度矩阵、加速度矩阵在初始化时一次性计算并缓存，避免每轮优化中重复生成。不变的雅可比矩阵（平滑度、速度边界）也做了缓存。

### 修复效果

| 指标 | 初始版本 | +平滑/约束修复 | +Hermite基函数 | 总改善 |
|------|----------|---------------|----------------|--------|
| 总代价 | ~1680 | ~21 | **~4.2** | ↓ 400× |
| 起始点误差 | ~0.33 rad | 0.019 rad | **0.0016 rad** | ↓ 206× |
| 终点误差 | ~0.25 rad | 0.020 rad | **0.0015 rad** | ↓ 167× |
| 端点速度 | ~5.8 rad/s | 0.54 rad/s | **0.018 rad/s** | ↓ 322× |
| 大目标(J1=2.5)代价 | — | ~233 | **~63** | ↓ 3.7× |
| 大目标端点速度 | — | 2.03 rad/s | **0.05 rad/s** | ↓ 40× |
| 大目标非线性度 | — | 0.10 (≈直线) | **0.33 (有曲线)** | ↑ 3× ✅ |

## 机器人参数

- **自由度**：6（全部 revolute 旋转关节）
- **连杆结构**：LINK_0 (基座) → LINK_1 → LINK_2 → LINK_3 → LINK_4 → LINK_5 → LINK_6 (末端/夹爪)
- **关节范围**：均为 ±3.14 rad (±180°)
- **碰撞检测**：球体近似，每个连杆 1~4 个球体 (定义在 `xtrainer.yml`)
